# Cierre de auditoría QA local — ClubOS
Fecha: 22/10/2026. Dictamen: requiere correcciones antes de aprobar producción.

## Alcance y método
Se cerró la campaña local autorizada con código original sin cambios, dependencias existentes, MariaDB independiente en 127.0.0.1:13316 y datos ficticios. Se conservaron los cambios de Git previos. No se accedió a la base real. La instancia QA se creó con el motor instalado (MariaDB 10.4.32); no permite certificar compatibilidad con versiones recomendadas más nuevas. Los módulos financieros probados solo registraron movimientos ficticios, sin transferencia de dinero.
La auditoría no equivale a cobertura exhaustiva de cada combinación ni a certificación de seguridad. El informe inicial conserva el reconocimiento y las pruebas anteriores; este cierre sustituye sus pendientes cuando hay evidencia posterior.

Evidencias: integration-results.json y extended-results.json. Estos dos scripts registran respuestas sin aserciones exhaustivas.

## Fallas confirmadas y prioridad
1. ALTA — health ante DB caída: backend/src/server.js llama t(error), inexistente. Reproducir GET /api/health con pool.query rechazando. Esperado 500/503 controlado; obtenido rechazo no manejado y timeout. Evidencia anterior UNHANDLED t is not defined. Corregir a next(error) y probar indisponibilidad.
2. MEDIA — fecha imposible: backend/src/routes/entrenamientos.js valida solo formato. POST /api/entrenamientos con división válida, fecha 2026-02-31 y hora 18:00 como administrador. Esperado 400/422; obtenido 500 al rechazar MySQL la fecha. Evidencia integration-results.json y error ER_TRUNCATED_WRONG_VALUE. Validar calendario antes de persistir.
3. MEDIA — respuesta exitosa no JSON aceptada: frontend/services/config.ts requestJson. Ejecutar network-check.mjs; fetch simulado ok:true con json() rechazado. Esperado error de protocolo explícito; obtenido resolución {}. Puede producir pantallas con datos ausentes o errores posteriores. No se reprodujo cada pantalla consumidora. Rechazar JSON inválido y validar forma de respuesta en fronteras críticas.
4. BAJA — rutas duplicadas en nivel incorrecto: frontend/app/_layout.tsx declara pago-familiar y comprobante-familiar fuera de (app). Abrir app y mirar consola: No route named ... exists in nested children. Esperado ausencia de advertencias; obtenido dos warnings. Comprobante dentro del grupo abre; no se afirma bloqueo del módulo. Mover declaraciones al layout correcto.
5. BAJA — README desactualizado: anuncia Expo 54 y alcance menor al real; package declara 57 y existen módulos financieros/viajes. Actualizar documentación y guía reproducible.
No se confirmaron fallas críticas en los escenarios ejecutados. Esto no prueba ausencia de vulnerabilidades.

## Seguridad, accesibilidad y rendimiento
Autenticación rechaza token inválido, refresh reutilizado y refresh tras logout. Autorización entre clubes comprobada sobre seis lecturas de entidades; socio restringido sobre cinco rutas. ID malicioso rechazado. Cobros y emisión concurrentes mantienen invariantes verificadas. No se realizó pentest exhaustivo, auditoría de paquetes contra una base de vulnerabilidades actualizada ni pruebas de despliegue TLS/CORS de producción.
Por inspección, quedan riesgos de localStorage para refresh web y borrado de sesión ante error transitorio de renovación. No se etiquetan como explotación confirmada.
En navegador hay campos con nombres accesibles, botones identificables y estados deshabilitados/carga; existen múltiples headings nivel 1 y títulos técnicos como admin, finanzas y morosidad. Recomendación baja de UX: jerarquía semántica y títulos legibles. No se certifican lector de pantalla, contraste completo, foco de teclado, mobile responsive ni objetivos táctiles nativos.
Los tiempos HTTP individuales están en advanced-results.json. Son mediciones locales con datos pequeños; no equivalen a un benchmark ni a una prueba de carga. No se aplicó carga sostenida.

## No verificables o fuera de cobertura final
Android/iOS (adb no encontrado en PATH; sin dispositivo validado), impresión/compartir nativos, archivos exportados, entorno publicado, TLS, integraciones externas, recuperación de contraseña/OAuth no implementados, pruebas prolongadas de carga y análisis exhaustivo OWASP. Tampoco se ejecutaron todos los botones/formularios ni todas las operaciones posibles de cada rol. Se documentan límites sin solicitar permisos adicionales ni declarar esas pruebas aprobadas.

Corregir los tres fallos de ejecución/validación, repetir las regresiones asociadas y validar Android/iOS y exportaciones antes de operar con datos reales. No se corrigió código por la restricción del usuario.
